## 2. Remaining Security Gaps & Backlog Prioritization

The following security findings identified in Phase A.1 remain outside the Phase A.2 scope and are prioritized for implementation in subsequent phases:

### 2.1 High Priority (P1)

1. **P1-SEC-03: Stored HTML / XSS Defense in Discovered Leads & Outreach History**
   - *Current State:* Crawled web snippets, contact names, and directory data are stored in SQLite and rendered in React. While React escapes strings in standard JSX, rich text previews, raw snippet rendering, or exported CSVs could lead to CSV formula injection or DOM-based script injection if rendered unescaped.
   - *Target Fix:* Introduce strict HTML sanitization (e.g. DOMPurify or server-side Bleach) for scraped text, and prefix formula triggers (`=`, `+`, `-`, `@`) with a tab or single quote during CSV export.

2. **P1-SEC-04: Secure Credential & API Key Storage**
   - *Current State:* API keys for search providers (Tavily, Google, Bing) and LLM providers (Anthropic, OpenAI, OpenRouter) are loaded from `.env` or process environment variables.
   - *Target Fix:* Integrate OS-level secret storage (Windows Credential Manager / DPAPI via `keyring` or Tauri native secure-store plugin) rather than plaintext `.env` storage on disk.

3. **P1-SEC-05: Rate Limiting & DoS Protection on Local API Endpoints**
   - *Current State:* While Bearer authentication protects against external unauthorized processes, authorized local scripts or rapid loops could overwhelm the SQLite database or spawn unbounded Playwright browser processes.
   - *Target Fix:* Add endpoint concurrency limits and per-minute sliding window rate limits (e.g., using `slowapi`).

### 2.2 Medium Priority (P2)

4. **P2-SEC-06: Database File Permissions & Encryption**
   - *Current State:* `storage/dispatches.db` is an unencrypted standard SQLite database with default Windows file permissions.
   - *Target Fix:* Restrict NTFS access control lists (ACLs) to the active local user, and evaluate SQLCipher for at-rest database encryption.

5. **P2-SEC-07: Email Content Security & Sandbox for Draft Generation**
   - *Current State:* Outreach email templates are generated by LLMs and human-reviewed prior to dispatch.
   - *Target Fix:* Add automated heuristic scanning for suspicious links, spoofed header fields, or unintentional disclosures in generated drafts prior to human approval.

6. **P2-SEC-08: Token Revocation & Multi-Session Rotation**
   - *Current State:* A single session token is generated per application instance in `storage/.session_token`.
   - *Target Fix:* Support dynamic token regeneration on application restart or operator logout, invalidating previously written session tokens.
